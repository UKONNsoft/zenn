:::message
**検証環境：Claude Code v2.1.232 / 2026-08 時点**
仕様の更新が速い領域です。重要な判断の前には公式ドキュメントで再確認してください。
:::

`CLAUDE.md` に「pnpm を使う」と書いたのに `npm` が走る。「コミット前にテスト」と書いたのに走らない。

この症状の原因は、大きく **6 つ**に分かれます。しかも**1 番目が一番多く、しかも一番知られていない**。順に潰していけば、たいてい特定できます。

---

## 先に結論：切り分けの順番

```text
① そもそも仕様として「保証」されていない  ← 最初に理解すべき前提
    ↓
② そもそも読み込まれていない              ← /memory で 30 秒で分かる
    ↓
③ 長すぎて他の情報に埋もれている          ← 200 行が目安
    ↓
④ 指示が曖昧で判定できない
    ↓
⑤ 別のファイルの指示と矛盾している
    ↓
⑥ /compact のあとに消えた
```

これでも効かない場合は、**そもそも指示で解決すべき問題ではない**という結論になります（後述）。

---

## ① そもそも「保証」されていない

ここが出発点です。公式ドキュメントにこう書かれています。

> CLAUDE.md コンテンツはシステムプロンプト自体の一部ではなく、システムプロンプトの後のユーザーメッセージとして配信されます。Claude はそれを読んで従おうとしますが、特に曖昧または矛盾する指示の場合、厳密な遵守の保証はありません。

つまり **CLAUDE.md は設定ファイルではなく、毎回渡される「お願いの文書」**です。

同じことがメモリのページでも明言されています。

> Claude はこれらをコンテキストとして扱い、強制的な設定ではありません。アクションをブロックするには PreToolUse hook を使用してください。

`.json` の設定ファイルと同じ感覚で「書けば効く」と思っていると、ここでずれます。**確率を上げることはできても、100% にはできない。** これが仕様です。

:::message
**この前提が分かると、以降の対処の意味が変わります。**
②〜⑥ は「確率を上げる作業」で、⑥ の先にある hook / permissions が「確実にする作業」です。
:::

---

## ② そもそも読み込まれていない

一番多い原因で、しかも**30 秒で確認できます**。

```
/memory
```

現在のセッションに読み込まれている `CLAUDE.md`・`CLAUDE.local.md`・ルールファイルが一覧表示されます。**ここに出ていなければ、Claude はそのファイルを見ていません。**

### 置き場所の確認

読み込まれる場所は決まっています。

| スコープ | 場所 |
|---|---|
| ユーザー指示（全プロジェクト） | `~/.claude/CLAUDE.md` |
| プロジェクト指示 | `./CLAUDE.md` または `./.claude/CLAUDE.md` |
| ローカル指示（個人・gitignore） | `./CLAUDE.local.md` |

### 起動した場所の問題

Claude Code は**現在のワーキングディレクトリからツリーを上に歩いて**、途中の各ディレクトリの `CLAUDE.md` を探します。

`foo/bar/` で起動すると、`foo/bar/CLAUDE.md` と `foo/CLAUDE.md` の両方が読まれます。逆に言うと、**サブディレクトリで起動していると、その下にあるはずの CLAUDE.md は読まれません**。

サブディレクトリの `CLAUDE.md` は、起動時ではなく **Claude がそのディレクトリのファイルを読んだときにオンデマンドで読み込まれます**。「最初から効いているはず」と思っていると外します。

### もっと詳しく調べる

どのファイルが、いつ、なぜ読み込まれたかをログに残せます。

> `InstructionsLoaded` hook を使用して、どの指示ファイルが読み込まれているか、いつ読み込まれているか、なぜ読み込まれているかを正確にログに記録します。これはパス固有のルールまたはサブディレクトリ内のレイジーロードファイルをデバッグするのに役立ちます。

`paths` 付きのルールや、ネストした `CLAUDE.md` の挙動を追うときはこれが確実です。

## ③ 長すぎて埋もれている

`CLAUDE.md` は**毎回のリクエストで全文がコンテキストに載ります**。長いほど他の情報に埋もれ、遵守率が下がります。

> CLAUDE.md ファイルあたり 200 行以下を目標にします。より長いファイルはより多くのコンテキストを消費し、遵守を減らします。

**200 行が目安。** 昔の資料では 300 行と書かれていることがありますが、現在の公式は 200 行です。

### 減らし方 1：`.claude/rules/` に分割する

特定のファイルにだけ関係する指示は、ルールに移して `paths` でスコープします。

```markdown:.claude/rules/api.md
---
paths:
  - "src/api/**/*.ts"
---

# API 開発ルール

- すべての API エンドポイントは入力検証を含める
- 標準エラー応答形式を使用する
```

`paths` を書くと、**一致するファイルを読んだときだけ**読み込まれます。全セッションで払っていたコストが、必要なときだけに変わります。

:::message alert
**罠：`~/.claude/rules/`（ユーザー階層）では `paths` による絞り込みが効きにくい。**
パスで絞りたいなら、プロジェクト階層の `.claude/rules/` に置きます。
:::

### 減らし方 2：参照資料は skills へ移す

「たまに必要になる知識」は skills に置くと、**使うときだけ全文が載ります**。CLAUDE.md に貼りっぱなしにすると毎回課金対象です。

### `@path` インポートは減らない

```markdown
プロジェクト概要については @README を参照してください。
```

これは整理には役立ちますが、**インポートされたファイルも起動時に展開されてコンテキストに入ります**。行数対策にはなりません。

### `/doctor` に見てもらう

```
/doctor
```

チェックインされた CLAUDE.md のトリミングを提案してくれます。Claude がコードベースから自力で導ける内容（ディレクトリ構成・依存リスト・アーキテクチャ概要）を削り、**ツールのデフォルトと違う落とし穴・根拠・規約を残す**方向の提案です。v2.1.206 以降で使えます。

---

## ④ 指示が曖昧で判定できない

「守られたかどうかを自分で判定できない指示」は守られません。**検証できる粒度まで具体化します。**

| ❌ 曖昧 | ✅ 具体的 |
|---|---|
| コードを適切にフォーマットする | 2 スペースのインデントを使用する |
| 変更をテストする | コミット前に `npm test` を実行する |
| ファイルを整理しておく | API ハンドラーは `src/api/handlers/` に置く |

書いたあとに「これは何をもって満たされたと言えるか？」と自問して、答えられなければ曖昧です。

### 構造も効く

マークダウンの見出しと箇条書きで関連する指示をまとめます。**Claude も人間と同じように構造をスキャンする**ので、整理されたセクションは密集した段落より従いやすくなります。

---

## ⑤ 別のファイルの指示と矛盾している

CLAUDE.md は**加算**されます。ユーザー階層・プロジェクト階層・サブディレクトリ、すべてが同時にコンテキストへ入ります。上書きではありません。

> 2 つのルールが互いに矛盾している場合、Claude は 1 つを任意に選択する可能性があります。

つまり**古い指示を消し忘れると、新しい指示と競合して不安定になります**。

点検する場所：

- `~/.claude/CLAUDE.md`（全プロジェクトに効いている個人指示）
- プロジェクトの `CLAUDE.md` / `CLAUDE.local.md`
- サブディレクトリにネストした `CLAUDE.md`
- `.claude/rules/` の各ファイル

`/memory` で読み込まれているファイルを一覧し、上から順に矛盾を探します。

### モノレポの場合

親ディレクトリの CLAUDE.md が勝手に効いていることがあります。関係ないものは除外できます。

```json:.claude/settings.local.json
{
  "claudeMdExcludes": [
    "**/monorepo/CLAUDE.md",
    "/home/user/monorepo/other-team/.claude/rules/**"
  ]
}
```

## ⑥ `/compact` のあとに消えた

長い会話で `/compact` すると、指示が効かなくなることがあります。挙動が場所によって違います。

| 対象 | `/compact` 後 |
|---|---|
| **プロジェクトルートの CLAUDE.md** | ✅ ディスクから読み直され、セッションに再注入される |
| **サブディレクトリのネストされた CLAUDE.md** | ❌ **自動では再注入されない**。そのディレクトリのファイルを次に読んだときに再度読み込まれる |
| **会話の中だけで伝えた指示** | ❌ 失われる |

3 つ目が一番多いパターンです。**チャットで伝えただけの指示は、圧縮を越えられません。** 残したいなら CLAUDE.md に書きます。

---

## それでも効かないなら、指示で解決すべきではない

①〜⑥ を潰しても守られないルールがあります。そこが**指示レイヤーの限界**です。

公式もこう案内しています。

> 特定の時点で実行する必要がある指示（例えば、すべてのコミット前またはファイル編集後）の場合は、代わりに hook として記述してください。Hook はシステムコマンドとして固定されたライフサイクルイベントで実行され、Claude が何をするかに関係なく適用されます。

### 使い分け

| やりたいこと | 使うもの | 確実性 |
|---|---|---|
| コーディング規約を守らせたい | CLAUDE.md | お願い |
| 特定のファイル種別にだけルールを効かせたい | `.claude/rules/`（`paths`） | お願い |
| **`.env` を絶対に読ませない** | `settings.json` の `permissions.deny` | **強制** |
| **編集後に必ず lint を走らせる** | `settings.json` の `hooks`（`PostToolUse`） | **強制** |
| **危険なコマンドをブロックする** | `hooks`（`PreToolUse`） | **強制** |

`permissions` と `hooks` は**クライアント側で判定される**ので、モデルの判断を通りません。だから確実に効きます。

```json:.claude/settings.json
{
  "permissions": {
    "deny": ["Read(./.env)", "Read(./.env.*)"]
  },
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{ "type": "command", "command": "npm run lint:fix" }]
    }]
  }
}
```

:::message alert
**「`.env` を読まないで」と CLAUDE.md に書くのは、保証になりません。**
秘密情報の保護は必ず `permissions.deny` 側で行います。
:::

## チェックリスト

効かないと思ったら、上から順に。

- [ ] `/memory` で対象ファイルが読み込まれているか確認した
- [ ] 起動したディレクトリの位置は正しいか確認した
- [ ] CLAUDE.md は 200 行以内か
- [ ] 指示は「検証できる粒度」で書かれているか
- [ ] 他のファイル（ユーザー階層・ネスト・rules）と矛盾していないか
- [ ] `/compact` の前後で挙動が変わっていないか
- [ ] そもそも hook / permissions で強制すべき内容ではないか

---

## まとめ

CLAUDE.md は**設定ファイルではなく、毎回渡されるお願いの文書**です。この前提を持つと、対処が 2 種類に分かれます。

- **確率を上げる**：読み込ませる・短くする・具体的にする・矛盾を消す
- **確実にする**：`permissions` と `hooks` に移す

「絶対に守らせたい」ものが CLAUDE.md に書いてあるなら、それは置き場所を間違えています。
